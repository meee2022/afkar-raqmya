# أثر للتقنية والتصميم

موقع عربي RTL على React وVite، وبيانات وإدارة عبر Convex.

## التشغيل والتحقق

Node.js 24 وnpm. انسخ `.env.example` إلى `.env.local` وأدخل رابط Convex. الدومين الرسمي الجديد يُضبط عبر `VITE_SITE_URL`؛ لا يُفترض أي دومين قديم. لا تضع كلمة مرور الإدارة في متغير يبدأ بـ `VITE_`.

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

## النشر

قبل النشر: راجع نسخة قاعدة البيانات المستهدفة وخذ نسخة احتياطية. انشر وظائف ومخطط Convex المحدثين إلى البيئة المعتمدة أولًا، ثم شغّل التهيئة الداخلية الإضافية `seed:seedProjects` على تلك البيئة. التهيئة لا تمسح المشاريع أو تعيد تفعيل المؤرشف ولا تستبدل المحتوى المعدّل. النسخة القديمة من دالة المسح أزيلت نهائيًا.

اضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` في بيئة Convex الخلفية و`VITE_CONVEX_URL` في بناء الواجهة. بريد الإدارة خاص بتسجيل الدخول ولا يُعرض كبريد تواصل عام. اضبط `VITE_SITE_URL` على الدومين الرسمي الجديد بصيغة `https://...`، دون مسار. إعداد البريد الرسمي من لوحة الإدارة؛ البريد القديم لا يُعرض.

ارفع `dist/` إلى الاستضافة المعتمدة. يلزم توجيه المسارات غير الموجودة فعليًا إلى `index.html` لدعم React Router، مع إعطاء الملفات الموجودة الأولوية. البناء يُنشئ HTML ببيانات مشاركة للصفحات الرئيسية، وخريطة موقع عند تحديد الدومين، ولقطات بيانات للمشاريع المنشورة إن كانت واجهة Convex المحدثة متاحة. لا يشمل ذلك عرض محتوى كامل على السيرفر.

### Cloudflare Pages

اربط المستودع بفرع `master`، واختر أمر البناء `npm run build` ومجلد النشر `dist`. ملف `.node-version` يحدد Node.js 24. أضف `VITE_CONVEX_URL` لرابط بيئة Convex المعتمدة و`VITE_SITE_URL` لرابط Pages النهائي أو الدومين المعتمد، في متغيرات البناء. لا تحتاج الواجهة إلى مفتاح نشر Convex أو كلمة مرور الإدارة على Cloudflare.

يستخدم Pages ملف `index.html` كبديل لمسارات SPA غير الموجودة، مع بقاء صفحات SEO الموجودة أولوية؛ لذلك لا تضف `404.html` أعلى مجلد النشر. ملف `public/_headers` يضيف ترويسات المتصفح ويمنع فهرسة وتخزين صفحة الإدارة، والتحقق الفعلي من صلاحية السجل يظل على Convex. افحص `/admin?section=registry` بعد النشر وتأكد أن القراءة دون جلسة إدارة مرفوضة.

التغييرات المحلية لا تنشر نفسها ولا تعدّل قاعدة البيانات البعيدة. تنفيذ أمر النشر أو التهيئة على بيئة حقيقية يحتاج تحديد البيئة المعتمدة.

## الحماية والبيانات

- دخول الإدارة بالبريد المعتمد وكلمة المرور، والتحقق منهما على السيرفر برسالة موحدة عند الخطأ. البريد يُقارن دون حساسية لحالة الأحرف أو المسافات المحيطة. الجلسات مخزنة كقيم مجزأة وتنتهي بعد 12 ساعة وترتبط ببريد الإدارة؛ الجلسات القديمة دون بريد أو التي لا تطابق البريد المعتمد تتطلب الدخول مجددًا. تسجيل الدخول محدود بـ20 محاولة لكل خمس دقائق على مستوى لوحة الإدارة، بما يشمل المحاولات ببريد آخر؛ هذا يقلل التخمين لكنه قد يؤخر المسؤول عند استهلاك النافذة.
- نموذج التواصل يتحقق على السيرفر، مع حقل خداعي وحد ثلاثة طلبات لكل رقم في الساعة وحد عام. هذا تقليل إساءة استخدام، وليس بديلًا عن حماية البوتات على حافة الاستضافة عند زيادة الحمل.
- المشاريع العامة من قاعدة البيانات فقط. `shared/projects.ts` كتالوج تهيئة وتكملة لوسائط الصفوف القديمة، ولا يعيد إظهار الصفوف المؤرشفة.
- الأرشفة قابلة للاستعادة ولا تمسح ملفات المشروع. رفع الملفات يتطلب جلسة إدارة، ويفحص النوع والحجم في الواجهة وعند إرفاق الملف بالمشروع على السيرفر.
- أرقام المستندات وحالاتها تتحقق خلفيًا. المستند المرسل لا يعود لمسودة، والتحويل لفاتورة من عرض معتمد فقط.

## سجل المواقع الخاص

القسم داخل لوحة الإدارة عبر `/admin?section=registry`. قاعدة `agencyWebsiteRegistry` منفصلة عن بيانات المعرض العام، وكل قراءة أو تعديل أو استيراد يمر عبر `requireAdmin`. إخفاء الحسابات في الشاشة يحمي من النظر العابر؛ صلاحية الوصول الفعلية تتحقق على السيرفر. النظام الحالي له حساب إدارة واحد، وأي شخص يحمل البريد وكلمة المرور أو جلسته المفعلة يملك نفس الصلاحية.

يسجّل أسماء المواقع والعملاء، الروابط، الدومين ومزوده وتجديده، المستودع، حساب كل خدمة ومشروعها ولوحتها، مرجع مدير كلمات المرور، والملاحظات والوسوم. لا توجد حقول لحفظ كلمات المرور أو مفاتيح API. الأرشفة قابلة للاستعادة، والتعديل يرفض الكتابة فوق نسخة أحدث. البحث محلي داخل القسم ولا يضع الحسابات في عنوان الصفحة أو Local Storage.

«من معرض الأعمال» يضيف مراجع المشاريع مرة واحدة دون نسخ بيانات خاصة إلى المعرض. الاستيراد على دفعات، يراجع صحة السجلات ولا يستبدل الموجود أو يعيد إظهار المؤرشف. نسخة JSON خاصة تتضمن الحسابات والملاحظات وحالة الأرشفة، لكنها لا تتضمن رمز جلسة الإدارة. احتفظ بنسختك في مكان خاص.

بيانات الصورة التي أرسلها المالك جُهزت محليًا في `.private/website-registry-import.json`، وكلها معلّمة للمراجعة. الملف مستبعد من Git ومن بناء الموقع ومن خادم Vite، ولا يُستورد أو يُرسل إلى Convex تلقائيًا. بعد نشر الخلفية المعتمدة: افتح السجل، ثم «النسخ والاستيراد» ← «استيراد ملف» واختره. لا يُخمّن رابط مستودع من بريد حساب GitHub، وذكر `athr.qa` في الصورة لا يغيّر الدومين الرسمي للموقع تلقائيًا.

إذا تعذر `convex codegen` بسبب عدم امتلاك الحساب المحلي صلاحية المشروع، فإن `src/admin/registryApi.ts` يحتوي مراجع RPC صريحة ومكتوبة الأنواع. هذا لا يتجاوز صلاحيات النشر ولا يغيّر الخلفية البعيدة؛ يلزم استخدام حساب Convex مخوّل عند النشر.

## الهوية

`PRODUCT.md` للحقائق والقيود، و`DESIGN.md` للاتجاه المعتمد. الألوان في متغيرات `src/index.css` وإعدادات Tailwind. الخط العربي محلي داخل `public/fonts`، مع بقاء Lexend الخارجي اختياريًا للكتابة الإنجليزية.
